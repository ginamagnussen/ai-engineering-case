# Mock data: NIG intercompany ledgers, October 2026 close

Generated by `data_gen/generate_mock_data.py` (seed 42; run it again to regenerate). Everything here is fictional.

## What the pipeline is allowed to see
| Path | Content |
|---|---|
| `raw/ledger_NIG-US.csv` | Oracle EBS: separate DR/CR columns, MM/DD/YYYY dates, counterparty identified by interco segment code (`200`) |
| `raw/ledger_NIG-UK.csv` | SAP S/4 (EN): signed amounts, DD.MM.YYYY dates, trading partner code (`DE01`) |
| `raw/ledger_NIG-DE.csv` | SAP ECC (DE): **semicolon**-delimited, **decimal comma**, German headers and text |
| `raw/ledger_NIG-AE.csv`, `raw/ledger_NIG-SA.csv` | Dynamics 365: ISO dates, counterparty identified by **legal name** |
| `raw/ledger_NIG-AU.csv` | Legacy system of the acquired Australian business: **free-text counterparty** (`"KSA branch"`, `"London office"`), D/C flag, DD/MM/YYYY dates |
| `raw/extract_manifest.json` | Period, extract date, comparison rule |
| `reference/entities.csv` | Entity master data. The `known_aliases` list is **deliberately incomplete** |
| `reference/fx_rates.csv` | Daily rates plus 2026 budget rates (USD per unit) |

Each extract holds the IC receivable (seller) and IC payable (buyer) postings dated 2026-10-01 to 2026-11-10. Postings after 2026-10-31 belong to November.

## Answer key (never feed it to the pipeline)
`ground_truth/labels.csv` has one row per real transaction: category, the line IDs on each side, the October difference in USD, the expected action, and a note. `ground_truth/summary.json` counts transactions by category.

| Category | What happened | Expected resolution |
|---|---|---|
| clean | Both sides agree | Match automatically |
| fuzzy_ref | Buyer's reference is missing, garbled, or only in the description | Match automatically on amount, date and parties |
| fx_difference | Buyer booked in its own currency at the **budget** rate | FX adjustment |
| timing | Buyer posted in November | None; clears next period |
| split | Buyer split the invoice across 2–3 cost centres | One-to-many match |
| miscoded_counterparty | Buyer booked against the wrong entity | Reclassify |
| amount_typo | Two digits transposed, or a keying error | Correct the amount |
| duplicate | Buyer posted the invoice twice | Reverse one line |
| missing_buyer | Buyer has no booking | Buyer books it |
| wht | Saudi buyer booked net of withholding tax (5% / 15% / 20%) | Match gross and reclassify the WHT |
| dispute | Buyer accepted only part of the invoice | **Escalate to a human** |
| accrual_no_invoice | Buyer accrued the cost but the seller never invoiced | Seller invoices, or buyer reverses the accrual |

Recurring fixed-amount fees (management fees, IT services) and repeated licence amounts are included on purpose, to make matching ambiguous.
